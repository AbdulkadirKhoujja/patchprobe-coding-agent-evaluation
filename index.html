03 / Evaluation methodology
From task brief to evidence-backed verdict.
The same sequence can be used to evaluate real coding agents; this packaged example uses a deliberately seeded flaw instead.
01 · Define
Set acceptance criteria
Specify tenant isolation, revision handling, validation and deterministic output.
02 · Exercise
Run the candidate
Start with public tests, then challenge unseen edge cases independently.
03 · Investigate
Identify root causes
Trace failures to the deduplication key, timestamp selection and unsafe validation.
04 · Review
Give an auditable verdict
Compare against a reference, reproduce findings and request concrete corrections.
Evidence boundary. The candidate code is an original deliberately flawed example, not a patch generated by a real model. No live coding agent, client repository, external benchmark or confidential data was used. The browser comparison is a lightweight simulator of the included Python algorithms; the scores above come from separately executed Python tests.
